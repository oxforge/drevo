Drevo can now update itself, and Tab completes file names in the command line.

## New: Check for Updates

- **One menu command.** Drevo ▸ **Check for Updates…** asks GitHub for the latest
  release. If you have it, Drevo says so. If there is a newer one, it shows the version
  and its release notes.
- **Install and Relaunch.** Drevo downloads the new version, replaces itself and opens
  again. **Later** leaves everything as it is.
- **Only what Drevo's author signed is installed.** The downloaded app must carry the
  same certificate as the Drevo you are running. If it doesn't, nothing is replaced and
  Drevo offers the release page instead. The same happens when Drevo can't write to the
  folder it is in, and for a copy you built yourself without a signing identity.
- **Nothing is cut off.** The app is replaced only when Drevo quits. If a copy, move or
  delete is still running, Drevo asks first, as it does on any quit; if you keep it
  running, the update installs the next time you quit.
- **No checks behind your back.** Drevo contacts GitHub only when you choose the command.

This release still has to be installed by hand, because 0.3.1 has no updater. Later
versions can be installed from the menu.

## New: Tab completes file names in the command line

- **Tab completes the name before the cursor**, from the active pane's folder or from
  the path typed so far (`~/` and absolute paths included). A folder gets a trailing
  `/`, a file a trailing space.
- **Several matches** extend to the part they share. When nothing more can be added, a
  menu lists them.
- **Names with spaces or quotes are escaped**, so the shell reads them as one name.
- It completes file and folder names, not command names.

## Fixes

- Tab in the command line no longer moves the keyboard focus to the panes or selects
  the text you typed. Shift-Tab stays in the command line too. Esc returns to the pane,
  as before.

## Install

Download `Drevo-0.4.0.dmg`, open it and drag Drevo to Applications. It needs macOS 14
Sonoma or later on an Apple Silicon Mac. The app is signed with a self-signed
certificate, so the first time you open it macOS says it couldn't verify it: click
Done, then go to System Settings ▸ Privacy & Security and click **Open Anyway**.
